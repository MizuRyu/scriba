# ADR-007 常時録音を会議の録音とは別の常駐プロセスにする

- 状態: 承認
- 日付: 2026-11-24
- 関連: [ADR-001](001-local-chunked-transcription.md)、[ADR-003](003-heavy-deps-in-subprocess.md)、[ADR-006](006-haas-default.md)、[F13](../specs/03-features.md)

## 文脈

会議の外で話したこと（独り言、考えを声に出したもの）も、文字にして残したい。そのためには、マイクを開いたまま録り続け、発話のある部分だけを残す動きが要る。

会議の録音（`start` / `stop`）は 1 回の会議を単位に作られている。`state.json` は同時に 1 録音だけを持ち、打ち切り、無音での自動停止、短い録音の破棄、無音の通知、出力デバイスの切り替えを備える。常時録音では、打ち切りと自動停止は録音を止め、無音の通知は話し終えるたびに出る。会議の録音と同時に動かす必要もある。

## 決定

- `scriba listen` の常駐プロセスを足す。`state.json` を使わず、会議の録音と独立に動かす。
- セッションは `{base_dir}/listen/` に置く。会議のセッションの一覧（ビューア、未転送の数え上げ）に混ぜない。文字起こし、マージ、保持期間の回収は、`Config` の置き場だけを替えて既存の関数を使う。
- OS の既定の入力を mic トラックとして録る。デバイス名は設定に持たない。既定の入力の ID が変わったとき、または音声が 10 秒届かないときは開き直す。イヤフォンの抜き差しに人の操作なしで追従するためである。
- 時が変わるたびに、チャンクの境目でセッションを替える。ストリームは開いたままにする。チャンク番号は 3 桁で、マージはセッションの全チャンクを読み直すため、1 セッションを 1 時間以内に収める。
- デバイスを開き直したら新しいセッションにする。本文の時刻はチャンク番号と長さから計算するので、途切れた時間をまたぐと以後の時刻がずれるためである。
- 発話の無いチャンクは、発話検出の直後に WAV を消す。発話が 1 つも無いセッションは、録音を終えた時点でセッションごと消す。話さない時間が大半で、その音声を残す理由がないためである。
- `listen_yield_apps` のアプリがマイクを使っている間は、文字起こしを始めない。録音は続ける。音声入力アプリの認識と GPU を取り合い、入力の表示を遅らせないためである。
- 予定との照合、frontmatter、転送は行わない。常時録音は会議ではない。

## 制約と見直し条件

- Mac がスリープしている間は録れない。
- 話者を区別しない。周りの人の声、再生した音、歌も、発話と判定されれば文字になる。それらの行が検索や要約を妨げる量になったら、区間の分類を検討する。
- 本文の時刻はセッションの開始からの経過で、開始時刻はファイル名（`yymmdd_hhmm.txt`）が持つ。本文に時計の時刻が要るようになったら、見出しの形式を見直す。
- 停止の指示は、文字起こし中のチャンクが終わってから反映される。その間はマイクも開いている。すぐに閉じる必要が出たら、文字起こしを録音の制御とは別のスレッドに分ける。
- モデルは常駐させず、チャンクごとに speech.cpp を起動する（ADR-003、ADR-006 のまま）。音声入力アプリと 1 つのモデルを共有するには、双方が同じ常駐の認識サーバーを使う必要がある。`listen_yield_apps` で待つだけでは足りなくなったら検討する。
- 未確認: launchd から起動した常駐プロセスにマイクの許可が付くか。確認する方法は、launchd のエージェントから `scriba listen run` を起動し、`logs/listen.log` に発話のあるチャンクが処理されるかを見ることである。付くまでは、マイクの許可を持つアプリから `scriba listen on` で起動する。
