# ADR-007 常時録音を会議の録音とは別の常駐プロセスにする

- 状態: 承認
- 日付: 2026-11-24
- 関連: [ADR-001](001-local-chunked-transcription.md)、[ADR-003](003-heavy-deps-in-subprocess.md)、[ADR-006](006-haas-default.md)、[F13](../specs/03-features.md)

## 文脈

会議の外で話したこと（独り言、考えを声に出したもの）を、文字にして残す。そのためには、マイクを開いたまま録り続ける動きが要る。話していない時間が大半を占めるので、残すのは発話のある部分だけにする。

会議の録音（`start` / `stop`）は、1 回の会議を単位に作ってある。その動きは、録り続ける用途と次のように合わない。

| 会議の録音の動き | 録り続ける用途に使ったときの結果 |
|---|---|
| `state.json` が同時に 1 つの録音だけを持つ | 録り続けている間は会議を録れない |
| タイムアウトと、無発話での自動停止 | 話していない間に録音が止まる |
| 無音の通知 | 話していないだけの無音を、音声の経路の断絶として通知する |
| 出力デバイスの切り替え | 相手の声を録らないので要らない |
| 発話の無い音声も保持期間まで残す | 残す理由のない音声が大半になる |
| 入力デバイスを名前で指定する | イヤフォンを替えるたびに設定の変更が要る |

## 決定

常時録音を、会議の録音から独立した常駐プロセス（`scriba listen`）にする。会議の録音と同時に動かせる。

### プロセスと置き場

- 常駐プロセスは `state.json` を読み書きしない。自分の PID だけを `{base_dir}/listen.json` に持つ。
- セッションは `{base_dir}/listen/` に置き、会議のセッション（`{base_dir}/sessions/`）と混ぜない。ビューアの一覧と未転送の数え上げは会議だけを対象にしているためである。
- セッションの中の構成（`meta.json`、`chunks/`、`transcripts/`）は会議と同じにする。文字起こし、マージ、保持期間の回収は、`Config` の置き場だけを替えて会議と同じ関数を使う。
- 予定との照合、frontmatter、転送は行わない。常時録音は会議ではなく、会議名も案件も持たない。

### 入力

- OS の既定の入力を mic トラックとして録る。デバイス名は設定に持たない。
- 既定の入力の ID が変わったとき、または音声が 10 秒届かないときは、入力を開き直す。イヤフォンの抜き差しに、人の操作なしで追従するためである。

### セッションの単位

- 時計の時が変わるたびに、チャンクの境目でセッションを替える。マージはセッションの全チャンクを読み直すので、1 セッションを 1 時間程度に収めて、マージの時間が延び続けないようにする。
- セッションを替えるときも、入力のストリームは開いたままにする。開き直すとその間の音声が欠け、無線のマイクは開くたびに音が届くまでの待ちが生じる。
- 入力を開き直したときは、新しいセッションにする。本文の時刻はチャンクの番号と長さから計算するので、途切れた時間をまたいで同じセッションに書くと、以後の時刻がずれる。
- セッション ID は開始時刻から作る。同じ ID のセッションが既にあれば、時刻を 1 秒ずつ進めた ID にする。入力が続けて切り替わると同じ秒に開き直すことがあり、同じ ID を使うと前のセッションの音声を上書きする。

### 休止

- `listen_pause_idle_min` を設定すると、設定した時間帯（既定は 0 時から 6 時）の間に、その分数だけキーボードとマウスの入力が無く、発話も無いときに、入力を閉じる。寝ている間にマイクを開いたままにせず、発話検出と音声の書き込みを止めるためである。
- 入力があったとき、または時間帯が終わったときに、入力を開き直す。入力を閉じている間は音声が届かないので、発話を再開の合図にできない。時間帯の終わりで必ず開き直すことで、入力が無いまま閉じ続ける状態を避ける。
- 無操作だけで閉じず、発話が無いことも条件にする。常時録音は、キーボードから離れて話す場面を録るための機能だからである。
- 既定は無効にする。入力を閉じている間に、キーボードに触れずに話した分は録れないためである。
- `listen_pause_on_battery` を設定すると、電池で動いている間は入力を閉じ、電源アダプタにつないだときに開き直す。入力を開いている間は coreaudiod が電力を使い続け、常時録音の常駐プロセスより大きい。文字起こしの処理時間は録音の長さの 1% に満たないので、電池の減りを抑えるには入力を閉じる必要がある。既定は無効にする。電池で動いている間に話した分は録れないためである。

### 残すものと消すもの

- 完成したチャンクを発話検出にかけ、発話が無ければ WAV をその場で消す。
- 発話が 1 つも無いセッションは、録音を終えた時点でセッションごと消す。
- 発話のあるチャンクの WAV と本文は、会議と同じ保持の設定（`retention_days`、`cleanup_target`）に従う。

### 文字起こし

- モデルは常駐させず、チャンクごとに speech.cpp を起動する（ADR-003、ADR-006 と同じ）。
- `listen_yield_apps` に書いたアプリがマイクを使っている間は、文字起こしを始めない。録音は続ける。音声入力アプリの認識と GPU を取り合い、そのアプリの表示を遅らせることを避けるためである。

## 却下した案

- **`scriba start` に録り続けるモードを足す。** `state.json` が 1 録音だけを持つので、会議と同時に録れない。同時に録れるように状態を複数にすると、`stop`、`status`、`discard`、自動録音がどの録音を指すかを全て決め直すことになる。
- **1 日を 1 セッションにする。** マージがその日の全チャンクを読み直すので、時刻が遅くなるほど 1 チャンクの処理が長くなる。
- **入力デバイスを設定で指定する。** 使うイヤフォンを替えるたびに設定の変更が要る。
- **認識のモデルを常駐させ、音声入力アプリと共有する。** 双方が同じ常駐の認識サーバーを使う構成が要り、ADR-003 の判断を変えることになる。`listen_yield_apps` で待つだけで足りている間は採らない。

## 制約と見直し条件

- Mac がスリープしている間は録れない。
- 入力を開いている間、macOS は操作が無いことによる自動のスリープをしない。`listen_pause_idle_min` で入力を閉じている間は、スリープできる。
- 休止の判定は、常駐プロセスが動いている Mac の入力だけを見る。別の端末で作業している時間を、寝ている時間と区別しない。
- 話者を区別しない。周りの人の声、再生した音、歌も、発話と判定されれば文字になる。それらの行が検索や要約を妨げる量になったら、区間の分類を検討する。
- 本文の時刻はセッションの開始からの経過で、開始時刻はファイル名（`yymmdd_hhmm.txt`）が持つ。本文に時計の時刻が要るようになったら、見出しの形式を見直す。
- ビューア、`scriba merge`、`scriba transcribe`、`scriba discard` は、常時録音のセッションを扱わない。本文を読み返す、辞書の変更を過去の本文に反映する、といった操作が要るようになったら、これらのコマンドに置き場の指定を足す。
- 停止の指示は、文字起こし中のチャンクが終わってから反映される。その間はマイクも開いている。すぐに閉じる必要が出たら、文字起こしを録音の制御とは別のスレッドに分ける。
- `cleanup_target = "all"` にすると、常時録音の本文も保持期間の後に消える。会議と常時録音で保持を分ける必要が出たら、常時録音用の設定を足す。
- 未確認: launchd から起動した常駐プロセスにマイクの許可が付くか。確認する方法は、launchd のエージェントから `scriba listen run` を起動し、`logs/listen.log` に `speech=True` の行が出るかを見ることである。確認できるまでは、マイクの許可を持つアプリから `scriba listen on` で起動する。
