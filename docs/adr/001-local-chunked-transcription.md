# ADR-001 録音はチャンク単位でローカルに文字起こしする

- 状態: 承認
- 日付: 2026-06-29
- 関連: [01 Overview](../specs/01-overview.md)、[05 Model Selection](../specs/05-model-selection.md)、[調査メモ](../research/2026-06-29-initial-investigation.md)

## 文脈

会議の文字起こしで求めるのは、低遅延より精度だった。会議中に流し読みできれば十分で、数分の遅れは問題にならない。音声を外部へ送らないことも条件だった。

ストリーミング認識（whisper.cpp のストリーミング、whisper_streaming）は短い窓で推論するため、文脈が足りず精度が落ちる。Apple Silicon の mlx-whisper は 120 秒の音声を 6 秒前後（large-v3-turbo）で処理でき、チャンク単位なら会議の進行に十分追いつく。

## 決定

- 録音を 120 秒（`chunk_duration`）ごとのチャンクに切り、チャンクごとに mlx-whisper で文字起こしする
- 文字起こしは端末内で完結させる。クラウドの ASR を使わない
- チャンク長は設定で変えられる。120 秒は文脈の長さと遅延の釣り合いで選んだ

## 見直し条件

- ローカルで動くストリーミング認識が、日本語の会議音声でチャンク方式と同等の精度を出せるようになったとき
- 会議中の発言にリアルタイムで反応する機能（字幕など）が要件に入ったとき
