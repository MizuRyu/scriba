# 背景と前提

コードを読んでも分からないこと（なぜ作ったか、何を前提にしているか、どう使われているか、なぜこの形か）をまとめる。仕様の細部は [specs/](specs/README.md)、判断の記録は [adr/](adr/README.md) にあり、ここはその手前の地図にあたる。

## これは何か

オンライン会議の音声を、自分の Mac の中だけで録音・文字起こしして、あとで読める・探せる・他の道具に渡せるテキストとして残す CLI。

- 使う人: 会議に出ている本人。1 台の Mac で、1 人が使う
- 残すもの: `[相手]` / `[自分]` の話者ラベルと時刻が付いた日本語の文字起こし（combined）。予定表と照合できれば、会議名・組織・案件を frontmatter に書く
- 残さないもの: 要約、議事録、話者の個人識別（相手側の複数人は区別しない）

## なぜ作ったか

- **会議の中身を手元に残したい。** 会議アプリの録画や文字起こしは、主催者の設定やテナントのポリシーに左右され、参加者の側からは使えないことが多い。scriba は参加者の手元で、聞こえている音だけを録る
- **音声を外に出したくない。** 会議の内容は外部に送れないことがある。Apple Silicon の mlx-whisper なら、端末内で会議の速度に追いつける（[ADR-001](adr/001-local-chunked-transcription.md)）
- **会議中から読みたい。** 2 分ごとに文字起こしするので、聞き逃した直前の発言を会議中に確かめられる
- **後段の道具に渡したい。** 文字起こしは素材であり、要約やノートへの振り分けは別の道具（LLM による要約、ノートアプリ）が行う。scriba はその受け口のフォルダに、案件ごとに分けて置くところまでを担う

## データの流れ

```
会議アプリ ──スピーカー出力──▶ 複数出力装置 ──┬─▶ ヘッドフォン（自分が聞く）
                                              └─▶ BlackHole 2ch ──▶ system トラック（相手の声）
マイク ─────────────────────────────────────────────────────────▶ mic トラック（自分の声、任意）

録音プロセス ──2分ごと──▶ chunks/*.wav
ワーカー ──Haas / mlx-whisper──▶ transcripts/*.json ──マージ・辞書・フィルタ──▶ combined（*.txt）
start 時: 予定表 ──照合──▶ meta.json の title / enrich
stop 時:  frontmatter を付ける ──案件が決まっていれば──▶ {export_dir}/transcript/{案件}/
後段（scriba の外）: 受け口のフォルダを見る要約・振り分けの道具
```

## コードに書かれていない前提

### 音声の経路

- **会議アプリのスピーカーを「複数出力装置」にしておく必要がある。** 会議アプリは OS の既定の出力ではなく、アプリ内で選んだデバイスに直接出す。ここが物理のヘッドフォンだと BlackHole に音が届かず、system トラックが無音になる。無音検知の通知はこの設定漏れを知らせるためにある
- **OS の出力を録音中だけ複数出力装置に切り替える。** 複数出力装置は仮想デバイスなので、イヤフォンを抜き差ししても OS が追従しない。普段は物理デバイスにしておき、`start` で切り替えて `stop` で戻す
- **ヘッドフォンを使う。** スピーカーで聞くと、マイクに相手の声が入って mic トラックに混ざる
- **入力デバイスを BlackHole にしない。** そうすると会議アプリに自分の声が届かない。`start` はこの状態を検出すると止まる

### 権限と起動元

- **マイクの許可は、録音プロセスを起動したアプリから受け継ぐ。** macOS は権限を「起動元のアプリ」単位で管理する。マイクの許可を持つアプリ（Raycast など）から `scriba start` や `scriba watch on` を実行する。許可のないターミナルから起動すると、エラーにならずに無音で録れることがある
- Raycast から起動すると PATH が最小限になる。ffmpeg や uv が見つからないときは、Raycast のスクリプトの PATH を見直す

### 実行環境

- **macOS 14.2 以降と Apple Silicon が前提。** 会議アプリの検知は macOS 14.2 で入った CoreAudio のプロセス情報を使い、既定の文字起こしは speech.cpp の Metal 版を使う
- **uv が要る。** 既定の Haas と Silero VAD は、初回に取得・検証した speech.cpp の別プロセスで呼ぶ。Whisper を指定した場合は `uvx` / `uv run --with` を使う（[ADR-006](adr/006-haas-default.md)）。初回はモデルと依存の取得に時間がかかり、ネットワークが要る
- **日本語の会議が前提。** CLI と UI の文言、幻聴フィルタ、会議名の正規化（`第3回` を取り除くなど）は日本語向けに作っている。`language` を変えれば他の言語も文字起こしはできるが、フィルタと文言はそのまま

### 使い方の前提

- **1 台・1 人・同時に 1 録音。** 録音中の状態は `{base_dir}/state.json` 1 つで持ち、2 本目の `start` は断る。複数の Mac でデータを共有する作りにはなっていない
- **自分が出ている会議を、相手の同意のもとで録る道具。** 録音や文字起こしの扱いは、所属組織や会議の取り決めに従う

## 設計の芯

- **精度を遅延より優先する。** ストリーミング認識ではなく 2 分チャンクで文字起こしする。会議中に読めれば十分で、数分の遅れは問題にしない
- **生データを正とし、combined は作り直せる派生物にする。** チャンクごとの Whisper の出力（`transcripts/*.json`）が生データで、combined はそこから辞書・フィルタ・トラックの選択を当てて作る。辞書を育てたら `scriba merge` で過去の会議にも反映できる。combined を手で直しても、merge で上書きされる
- **分類は決定論的に行い、LLM を使わない。** 予定との照合、組織と案件の推定は、時刻・ドメイン・キーワード・学習した仕訳ルールだけで決める。結果が説明でき、同じ入力には同じ結果を返す。判断の難しいものは未分類のまま人に返す
- **失敗しても録音は止めない。** 予定が取れない、VAD が失敗する、辞書の上限を超える、といった場合も、録音と文字起こしは続ける
- **安全弁を重ねる。** 無音の通知（経路の断絶）、タイムアウト（切り忘れ。既定 3 時間）、自動停止（system と mic の両方が丸ごと無音）、自動録音の会議終了の検知。消える方向の処理は控えめにする（未文字起こしの WAV は保持期間を過ぎても消さない。タイムアウトで止まった録音は自動で転送しない）

## 普段の使われ方

1. ログイン後に一度、Raycast から自動録音を有効にする（`scriba watch on`）
2. 会議に入ると録音が始まる。予定表に会議があれば会議名が付く
3. 会議中は `scriba view --serve` で文字起こしの伸びを見られる
4. 会議が終わると録音が止まり、残りを文字起こしして通知する。会議名と案件が決まっていれば、受け口のフォルダに転送される
5. 予定外の会議は未分類のまま残る。`scriba status` が未転送の件数を出すので、`scriba export <id> --project <案件>` かビューアで案件を選んで転送する。選んだ案件は仕訳ルールとして覚え、次の同じ定例は自動で分類される
6. 誤変換が目立ったら辞書に足し、`scriba merge` で作り直す

## データの寿命

| もの | 置き場 | 消えるとき |
|---|---|---|
| 録音（WAV） | `sessions/<id>/chunks/` | `retention_days`（既定 7 日）後の `start` / `cleanup`。未文字起こしなら残す |
| Whisper の出力・VAD の結果 | `sessions/<id>/transcripts/*.json` | 消さない（`cleanup_target = "all"` ならセッションごと消える） |
| combined | `sessions/<id>/transcripts/*.txt` | 消さない。merge と enrich で書き直す |
| 転送したもの | `{export_dir}/...` | scriba は消さない（後段の道具の持ち物） |
| 仕訳ルール | `classification_rules.jsonl` | 消さない。誤った学習は手で行を消す |
| 性能のログ | `logs/performance.jsonl` | 消さない |

セッションを丸ごと消すのは `scriba discard` だけ。

## 既知の制約

- 相手側の複数の話者は区別しない（system トラックは 1 人として扱う）
- 会議アプリの検知はマイクの使用で判断するので、参加前の待機画面でも録音が始まる（`min_keep_sec` 未満で終われば破棄）。マイクを使う会議以外のアプリを `meeting_apps` に入れると、誤って録音が始まる
- Whisper はチャンクの末尾や無音で定型句を幻聴する。フィルタと VAD で減らしているが、ゼロにはならない
- 予定との照合は開始時刻の ±10 分だけを見る。大きく遅れて始めた会議には会議名が付かない（`scriba title` で後から付ける）
- `view --serve` のページは htmx を CDN から読む。オフラインでは自動更新が効かない（静的な `scriba view` は動く）
- 録音・通知・会議アプリの検知・文字起こしの実行は、自動テストでは確かめられない。変更したら実機で一度録る

## 旧バージョンからの変更

公開に合わせて、個人の環境に固定されていたところを設定に移し、いくつかの不具合を直した。旧バージョンで録ったセッションはそのまま読める。

| 変わったこと | 旧 | 新 | 旧バージョンの利用者がすること |
|---|---|---|---|
| 予定の取得元 | 決め打ちの同期フォルダの JSON。見つからなければ同期アプリを起動 | `calendar_source`（`json` \| `ics`）と `calendar_path` で指定（[ADR-004](adr/004-calendar-source-adapters.md)） | 既定のパスで読んでいたなら、`calendar_path` にそのパスを書く |
| 転送先 | 個人のフォルダが既定 | `export_dir` の既定は空（転送しない）。`export_subdir` で配下の形を変えられる | `export_dir` を書いていなければ書く |
| 相手側のトラック名 | `teams` | `system`（[ADR-005](adr/005-system-track-name.md)）。旧名も読む | なし |
| 会議アプリ | Teams 決め打ち | `meeting_apps` | なし（既定は Teams） |
| 時刻 | 日本時間に固定 | OS のタイムゾーン | なし |
| frontmatter | 会議名入りのファイル名にしてから付かなくなっていた | `stop` と `scriba enrich` で付く | 付いていない過去の会議は `scriba enrich <id>` で付けられる |
| ビューアからの設定保存 | ドメインのキーを引用符なしで書き、次の読み込みで壊れた | 引用符で囲む。配列の設定も保つ | ビューアで保存して壊れた config.toml は `[enrich.organizations]` のキーを `"..."` で囲んで直す |
| 通知 | 文言に `"` があると表示されなかった | 引用符を含んでも表示される | なし |
