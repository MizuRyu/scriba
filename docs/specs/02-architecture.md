## 状態管理

- 録音プロセス・ワーカーの PID と切り替え前の出力デバイスを `{base_dir}/state.json` に保存
- 録音中かどうかは state.json の有無 + 録音プロセスの生存確認で判定
- セッション = 1回のstart〜stopを1セッションとして管理

## ディレクトリ構成

```
{base_dir}/                          # 設定で指定可能
├── config.toml                      # 設定ファイル
├── dict.yaml                        # 辞書（initial-prompt用語 + 置換パターン）
├── sessions/
│   └── {session_id}/                # e.g. 20260629-143000
│       ├── chunks/
│       │   ├── system_000.wav       # 相手の声（BlackHole 2ch。旧名 teams_000.wav）
│       │   ├── mic_000.wav          # 自分の声（外部マイク）
│       │   └── ...
│       ├── transcripts/
│       │   ├── system_000.json
│       │   ├── mic_000.json / mic_000.vad.json
│       │   └── yymmdd_hhmm[_会議名].txt  # combined。時刻順マージ（[自分]/[相手]ラベル付き）
│       └── meta.json                # セッション情報
├── logs/
│   └── performance.jsonl            # 全セッション共通
└── state.json                       # 録音中の状態
```

## 実装言語

Python 3.11+。依存は uv が管理する。録音、ワーカー、自動録音は別プロセス。ビューアは Python 標準ライブラリの HTTP サーバーと HTML / CSS / JavaScript を使う。

## モデルの実行

Haas と Silero VAD は speech.cpp の別プロセスで呼ぶ。実行ファイルは `{base_dir}/models/speech-0.10.0/`、重みは speech.cpp のキャッシュに置く。従来の Whisper を指定した場合は `uvx` / `uv run --with` を使う。モデルを常駐させない判断は [ADR-003](../adr/003-heavy-deps-in-subprocess.md)、Haas の取得と発話区間の扱いは [ADR-006](../adr/006-haas-default.md)。
